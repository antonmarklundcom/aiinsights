## Decisions
- `category` stays `varchar` in 0001 even though 0001 creates the `item_category` type.
  Existing rows hold free-text values that no `USING` cast would accept, and plan §5.2 puts
  the mapping in O2's hand-written `0002`. So O1 ships the type, O2 maps the data and casts
  the column. An unused `pgEnum` still emits `CREATE TYPE`, so no hand-editing was needed.
- `typecheck` runs `next typegen` first: `src/app/layout.tsx` uses the generated global
  `LayoutProps<"/">`, so bare `tsc --noEmit` fails on a clean checkout.
- `env.ts` is a proxy over a memoised `loadEnv()`. Importing it never throws; touching a key
  does. `loadEnv(source)` is exported pure so the production rule is testable without
  mutating `process.env`.
- Blank and whitespace-only values count as missing — Vercel hands back `""` for a var that
  was added but never filled in.
- CI also re-runs `db:generate` and fails on a dirty `drizzle/`. Not in §5.1, but it is the
  only thing that stops schema drift once four phases are editing in parallel.
- `next build` runs in production mode, so it enforces the production-only keys. Both CI and
  the README use placeholders rather than relaxing the rule.

## Known issues
- **For S2:** there is no `vitest.config.ts`, so Vitest does not resolve the `@/*` tsconfig
  alias — a static `import "@/db/schema"` in a test fails. `db-mock.ts` and its test use
  relative specifiers for that reason. S2 owns `vitest.config.ts` and needs to add the alias
  before it can `vi.mock("@/db")` the way the webhook imports it.
- `db-mock.ts` does not interpret Drizzle `eq()`/`and()` conditions; it records them and lets
  a test narrow rows with `selectWhere` / `updateWhere` / `deleteWhere`. Deliberate — parsing
  query chunks would be brittle. S2 extends it.
- The unique index in 0001 will fail to create if production already holds two rows for the
  same `(chat_id, message_id)`. Nothing in the old code path could write one, so this is
  noted rather than guarded.
- No database was reachable from this session (plan §4.15): migrations are verified by
  `drizzle-kit generate` producing a clean diff, not by being applied.
- `public/*.svg` leftovers and the `globals.css` Arial override (report §7) are S1's files.
