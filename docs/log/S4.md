# S4 — Full-text search

## Built
- `drizzle/0003_search.sql`: generated stored `search tsvector` column on `items`
  (title + tags weight A, summary weight B, note + caption weight C) and a GIN index on it.
- `src/db/schema.ts`: `tsvector` via `customType` (Drizzle has no built-in tsvector column),
  `search` column with `generatedAlwaysAs`, `items_search_idx` GIN index.
- `src/lib/search.ts` + test: `buildSearchCondition(q)` — `websearch_to_tsquery('simple', q)`
  at 3+ chars, escaped `ILIKE` fallback below that. `searchRank(q)` alongside it for a future
  relevance sort. `escapeIlike` exported and tested on its own.
- `src/app/page.tsx`: the `q`-condition block now calls `buildSearchCondition`; unused
  `ilike`/`or` imports dropped. Layout and `orderBy` untouched.

## Decisions
- `tags` is jsonb; a generated column can't hold a subquery, so `jsonb_array_elements_text`
  is out. Used `translate(tags::text, '[]"', '   ')` instead — strips the JSON punctuation,
  leaves words comma-separated, `to_tsvector` tokenizes past the commas. Verified against a
  disposable local Postgres 16 (`initdb`/`pg_ctl` were present in this sandbox): the migration
  applied, the generated column populated correctly, and `websearch_to_tsquery` matched both a
  title word and a tag word on a seeded row.
- `search.ts` exports `searchRank` even though `page.tsx`'s `orderBy` is out of phase scope
  (hard limit: edit only the `q` condition lines) — it's the "ranked with ts_rank" half of
  plan §6.4 the dashboard phase can use without another schema/query-shape change.
- Short-query threshold is 3 chars, matching plan §6.4 exactly; `escapeIlike` covers `%`, `_`,
  and a literal backslash so the fallback can't be turned into an unintended wildcard.
