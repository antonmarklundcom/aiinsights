# S2 — Tests for the pipeline libs and webhook

## Built
- `page-meta.test.ts`: og:title/description extraction, single- vs double-quoted attributes,
  attributes in varying order/position, entity decoding, `<title>` fallback (and precedence
  over it), non-2xx and a throwing `fetch` → nulls.
- `youtube.test.ts`: caption-track extraction from a fixture watch-page snippet
  (`src/test/fixtures/youtube-watch-with-captions.html`), english-track preference, json3
  event flattening across multiple caption events, no-tracks/failed-fetch → null transcript.
- `telegram-format.test.ts`: `escapeHtml`; `formatReply`'s needs-note branch, full render,
  per-field HTML escaping of item content, and omitted sections; `formatDuplicateReply`'s
  title/url fallback and its dashboard link gated by `APP_URL`.
- `telegram.test.ts`: extended with `sendTelegramMessage` — success payload shape, a non-2xx
  status logged and returning `false`, `ok: false` on an HTTP 200 also treated as failure, a
  thrown fetch swallowed, and a non-JSON error body falling back to raw text.
- `webhook.test.ts` (O2's): already covered all five cases plan §6.2 lists; left untouched.
- `vitest.config.mts`: added a `coverage` block (`provider: "v8"`, `reporter: ["text"]`,
  `include: ["src/lib/**"]`, matching the phase's coverage target).
- `package.json`: `test:coverage` script.

## Decisions
- Added `@vitest/coverage-v8` (pinned to the installed Vitest's own `4.1.11`) as a
  devDependency — outside `Owns`' "`test:coverage` script only", but the script cannot run
  without it.
- `webhook.test.ts` already satisfied every case §6.2 names (O2 wrote it against its own exit
  criteria first); no duplicate assertions added.
- The YouTube fixture keeps `\u0026`-escaped query strings, matching what YouTube's page
  actually emits, so the transcript fetcher's own unescape step is exercised rather than
  bypassed.
- `page-meta.ts`'s regex requires `property=` before `content=` within a tag; a
  content-before-property tag is asserted as a documented non-match (falls through to the
  `<title>` fallback), not treated as a bug to fix — out of scope for a tests-only phase.
